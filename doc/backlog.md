## 0. 이 문서를 읽는 법

**흩어져 있던 남은 일을 한곳에 모은 목록이다.** 이전에는 design.md §13(감사가
찾아낸 결함), §10(Phase 로드맵), performance.md §9(최적화 우선순위), README
("아직 없는 것")에 나뉘어 있어 "다음에 뭘 하지"에 답하려면 네 곳을 봐야 했다.

**우선순위의 근거는 목적 함수다.** 이 앱이 최소화하는 것은 누적 전송 바이트가
아니라 **사용자가 네트워크를 기다리는 시간**이다 (ADR-56, design.md §1.4).
요금제 제약은 없고 회선이 느릴 뿐이다. 그래서:

- CPU 시간도 대기 시간이다 — `절약한 전송 시간 > 추가 CPU 시간`일 때만 이득
- 누적 총량 관리는 폐기됐다 (ADR-57)
- 임계 경로 **밖**의 전송은 총량이 늘어도 이득이다 (ADR-7)

**상태 표기**

| 표기 | 뜻 |
|------|-----|
| 🔴 | 사용자에게 잘못된 결과나 손실을 줄 수 있다 |
| 🟡 | 기능 공백 — 앱 밖으로 나가야 하는 일이 남아 있다 |
| 🟢 | 개선 여지 — 지금도 동작한다 |
| ⚪ | 결정 대기 — 무엇을 할지부터 정해야 한다 |

## 2. 기능 공백

### 2.1 원격 관리 (Phase 3 증분 5)

🟡 원격 추가·삭제·주소 변경이 없다. 지금은 git CLI로 나가야 한다.

`RemoteEngine.list_remotes()`와 `remote_url()`은 이미 있다.

### 2.2 줄 단위로 골라 합치기

🟢 지금은 파일 단위 선택(내 것/상대 것)과 편집기로 마커를 정리하는 경로 둘이다.
양쪽에서 일부씩 가져오려면 편집기를 써야 한다.

부분 스테이징(§4.2)의 패치 합성 기계를 재사용할 수 있을 것으로 보인다.

### 2.3 파일시스템 감시

🟢 외부 CLI 조작이 화면에 자동 반영되지 않는다 — F5로 수동 갱신한다.
`watchdog` 도입 시 §3.3 스레딩 규칙과 디바운스 설계가 필요하다.

**참고**: design.md §4.5

## 3. 정확성 결함 (감사에서 확정됨)

> design.md §13에서 옮겨왔다. **적어두지 않으면 "감사를 통과했다"로 읽힌다.**

### 3.3 해결 버튼이 워킹 파일을 UI 스레드에서 한 번 읽는다 🟢

> 원래 항목("`conflict_detail()`이 UI 스레드에서 blob 전체를 읽는다",
> 파일 크기의 약 3배)은 DCR-002로 대부분 해소됐다 — 상세는
> `ConflictLoader`가 워커에서 읽고, 해결 버튼 경로는 워커가 읽어둔
> 원본을 재사용한다. **남은 것**: 클릭 시점의 편집 여부 판정이 워킹
> 파일 1회 읽기를 UI 스레드에서 한다. 편집은 상세 도착 이후에도
> 일어날 수 있어 클릭 시점의 내용이어야 하기 때문이다. 3배 → 1배.

### 3.4 ahead/behind가 UI 스레드를 벌어진 만큼 쓴다

🟢 코드 주석 세 곳이 "실측 0.002ms"를 근거로 UI 스레드 실행을 정당화하는데,
그 값은 **한쪽 1커밋짜리 픽스처**에서 나왔다. 갈라진 만큼 선형이다 (감사 실측):

| 갈라짐 | 중앙값 | 최대 |
|--------|-------|------|
| 100 + 100 | 0.41ms | 2.3ms |
| 1,000 + 1,000 | 1.22ms | 8.9ms |
| 10,000 + 10,000 | 14.5ms | **84.8ms** |

§1.3이 모노레포 사용자를 대상으로 명시하므로 가상의 입력이 아니다.
**ADR-11("픽스처는 현실을 대표해야 한다")과 같은 부류의 흠**이다 — 주석의
숫자부터 고쳐야 다음 사람이 잘못된 안심을 물려받지 않는다.

### 3.5 부분 복제에서 없는 객체를 만났을 때의 처리가 없다

⚪ `_translate`가 OID를 버리고 일반 오류로 뭉개, 사용자는 무엇이 없는지도
어떻게 받는지도 알 수 없다. 부분 복제는 선택지로만 제공되고 기본값이 아니라
(ADR-6 확정) 급하지 않다.

### 3.6 실패한 clone의 계측이 남지 않는다

⚪ ADR-26("실패해도 쓴 트래픽은 기록한다")과 §4.9("귀속시킬 대상이 없다")가
서로 다른 말을 한다. **저장소가 없는 작업의 계측을 어디에 귀속시킬지**부터
정해야 한다.

### 3.8 죽은 코드가 테스트로 유지되고 있다 🟢

- `RemoteEngine.ahead_behind` — §4.7.6이 pygit2로 옮겼다고 서술한 CLI 구현이
  남아 있고, docstring은 "push/pull 버튼이 이 값에서 나온다"고 **거짓 주장**한다.
  UI는 `LocalGitEngine` 쪽을 쓴다.
- `StatsStore.summarize()` / `TransferSummary` / `billed_bytes` — ADR-57이
  소비자(누적 대시보드)를 없앴는데 기계가 남았다. `src/`에서 호출 0건.
- `LocalGitEngine.is_merging()` — 프로덕션 호출자 0건. 판정은 전부
  `current_operation()`으로 옮겨갔다.

셋 다 테스트가 존재를 지지하고 있어 단순 삭제가 아니라 결정이 필요하다.
`models.py`가 스스로 세운 기준("아무도 읽지 않는, 권위 있어 보이는 죽은
코드는 없는 것보다 나쁘다")이 적용될 자리다.

### 3.9 테스트 자체의 결함 🟡

- `test_design_consistency.py::test_record_skips_when_there_is_no_repository`는
  **완전히 공허하다** — `recorded = []`를 만들어 아무 데도 넘기지 않고
  `assert recorded == []`를 한다. 무조건 참이다.
- 같은 파일의 `test_ui_does_not_shell_out_for_divergence`는 소스 문자열만
  본다. `subprocess.run(["git","rev-list",...])`을 인라인으로 넣으면 통과한다 —
  정확히 금지하려던 그것이다.
- `test_graph.py::TestCrossMerge`는 교차 머지가 아니다. 픽스처가 중첩 머지라
  **레인 할당기의 진짜 criss-cross 동작은 미검증**이다.
- `bench_load.py`는 pytest가 수집하지 않는다 — §8이 말하는 성능 회귀는
  실제로는 수동 스크립트다.

## 7. 다시 논의하지 않기로 한 것

**폐기된 결정을 다시 꺼내지 않으려고 적어둔다.** 근거가 무너진 것들이다.

| 항목 | 왜 안 하는가 |
|------|-------------|
| 월간 트래픽 예산 · 상한 · 누적 대시보드 | **요금제 제약이 없다** (ADR-57). 청구서가 없는데 예산을 관리할 이유가 없고, 상한은 필요한 순간에 작업을 막는다 |
| prefetch 온보딩 질문 | 물어볼 비용이 없다 (ADR-7). 대신 `저장소 > 배경에서 미리 가져오기`로 끌 수 있다 |
| 압축 수준 최대화 | 팩 크기 이득이 **0.00~0.08%**에 그치는데, 압축이 잘 안 듣는 내용에서는 시간을 **2.35배** 쓴다 (ADR-8 정정, performance.md §6.4.2). 기본값(6)을 명시하는 이유는 성능이 아니라 사용자가 `0`으로 꺼둔 경우를 막는 하한선이다 |
| `pack.window`/`pack.depth` 델타 설정 (push) | 바이트 −0.5~4%에 소요시간 **+20%** (ADR-35). 유휴 repack에서만 쓸 값이다 |
| 남은 시간(ETA) 표시 | 역산이 구조적으로 낙관 편향 (ADR-59). 팩이 커밋→트리→blob 순으로 쓰여 객체당 바이트가 뒤로 갈수록 커진다 |
| `core.fsmonitor` / `untrackedCache` | **소비자가 없다** (ADR-82). 이 설정을 읽는 것은 `git status`인데 앱의 상태 조회는 전부 pygit2(libgit2) 경로다 — 켜면 데몬만 남고 아무도 빨라지지 않는다. 재평가 조건: 앱이 git CLI status를 쓰게 되거나 파일시스템 감시(§2.3)를 설계할 때 |

## 8. 이 문서를 갱신하는 법

- 항목을 **끝내면 지운다.** 완료 목록이 아니라 남은 일 목록이다.
- 감사나 리뷰에서 새 결함이 확정되면 §3에 넣는다 — 고치지 않을 것이라면
  **왜 안 고치는지**를 함께 적는다. 이유 없이 남은 항목은 다음 사람이
  판단할 수 없다.
- 결정이 폐기되면 §7로 옮긴다. 지우면 같은 논의가 반복된다.
- design.md의 §13은 이 문서로 대체됐다.
