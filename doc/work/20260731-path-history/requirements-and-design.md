# 요구사항 + 설계 — 경로 히스토리 + commit-graph `--changed-paths` 측정·결정

> 기준선: 초안 (2026-07-31 — 승인 대기). 하나의 회차인 이유: backlog의
> commit-graph 항목(ADR-14)이 "소비 기능이 생겨야 측정에 의미가 있다"로
> 보류돼 있어, 소비 기능(경로 히스토리)과 측정·결정이 한 몸이다.

## 1. 배경 — 왜 이 둘이 한 회차인가

commit-graph의 `--changed-paths`(Bloom 필터)는 **경로로 좁힌 히스토리
조회**를 가속하는 장치다. 순회 가속은 실측 오차 수준이라(ADR-14) 이미
기각됐고, 남은 효용은 경로 조회뿐인데 앱에 그 기능이 없어 측정 자체가
무의미했다. 기능을 만들면 측정이 의미를 얻고, 측정이 끝나면 backlog의
마지막 ⚪가 닫힌다.

## 2. 요구사항

- FR-01 커밋 상세의 변경 파일 목록에서 파일 하나를 골라 **그 경로를
  바꾼 커밋들**을 시간 역순으로 본다 (sha·요약·작성자·날짜).
- FR-02 목록에서 커밋을 고르면 **그 커밋에서 이 파일이 어떻게 바뀌었나**
  (diff)를 같은 화면에서 본다 — 기존 DiffLoader의 경로 좁히기 재사용.
- FR-03 조회는 UI 스레드를 막지 않는다 (G4 예산 — 로더 패턴).
- FR-04 이름 변경(rename) 추적은 v1 범위 밖 — 파일이 개명되면 개명
  시점에서 목록이 끊긴다. 화면에 이 한계를 밝힌다.
- AC-01 파일을 바꾼 커밋만 나온다 (안 바꾼 커밋이 섞이면 실패).
- AC-02 병합 커밋의 처리가 `git log -- <path>`와 같은 결과를 낸다
  (동일 저장소에서 CLI 출력과 대조하는 테스트).
- AC-03 1만 커밋 저장소에서 첫 결과 표시가 G4 예산 안에서 시작된다
  (조회 자체는 워커, UI는 도착분부터 그린다).

## 3. 설계

### 3.1 엔진 경로 — **측정이 정한다** (프로토타입 선행, wf-design §1)

두 후보의 비용 구조가 달라 실측 없이 고를 수 없다:

| 후보 | 원리 | 예상 강점 |
|------|------|----------|
| A. pygit2 순회 | 커밋마다 트리에서 경로의 blob OID를 부모와 비교 | 프로세스 기동 없음, 점진 전달이 자연스러움 |
| B. git CLI `log -- <path>` | git의 경로 필터 | **commit-graph Bloom 필터의 수혜자** — 트리 파싱을 건너뛴다 |

**가설**: 작은 저장소는 A가 이기고(기동 비용), 큰 저장소는 Bloom 필터가
있을 때만 B가 이긴다. **판단 기준**: 1만 커밋급 합성 저장소에서 (1) A,
(2) B(Bloom 없음), (3) B(Bloom 있음)의 완주 시간과 첫 결과 도달 시간.
프로토타입은 벤치 스크립트로만 쓰고 제품 코드에는 승자만 넣는다.

### 3.2 commit-graph 쓰기 자리 — idle_repack

측정에서 Bloom이 이기면: `idle_repack()`에
`git commit-graph write --reachable --changed-paths`를 얹는다 — 유휴
CPU는 공짜라는 같은 근거(ADR-84)를 공유하는 자리다. 지면: 얹지 않고
ADR-14를 "경로 조회에서도 이득 없음, 종결"로 갱신한다. 어느 쪽이든
**backlog의 마지막 ⚪가 닫힌다.**

### 3.3 UI

- 변경 파일 목록(`_file_list`)에 컨텍스트 메뉴 "이 파일의 히스토리" 추가.
- 다이얼로그: 위 = 커밋 목록(도착분부터 채움), 아래 = 선택한 커밋의
  해당 파일 diff. 로더는 세대 토큰 방식(기존 DiffLoader 패턴), 창 닫힘
  시 `@_drops_late_deliveries` 가드 적용 대상.
- 문구는 전부 카탈로그 경유 (`tr`/`trf` — f-string 상한 0이 강제).

### 3.4 검증 계획

- 엔진: CLI 대조 테스트(AC-02), 개명·삭제 경로 경계, 병합 커밋.
- UI: 다이얼로그 종단(선택→diff), 늦은 배달 가드.
- 벤치: `tests/benchmarks/`에 측정 스크립트 남김 (결정 근거 재현).
- 전체 스위트 + 3-OS CI 녹색.
