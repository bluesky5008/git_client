## F1 — 원격 관리 (backlog §2.1, Phase 3 증분 5)

### 요구사항

- FR-01 원격 목록(이름·주소)을 앱 안에서 본다.
- FR-02 원격을 추가·삭제하고 주소를 바꾼다. 삭제는 원격 추적 참조까지
  지우므로 확인을 받는다 (§5.2 원칙 2).
- AC-01 추가한 원격으로 fetch가 되고, 삭제하면 추적 참조가 사라지며,
  주소 변경 후 fetch가 새 주소를 쓴다.

### 설계

- **쓰기 주체는 pygit2다** (ADR-2 경계: 네트워크는 CLI, 로컬 쓰기는
  pygit2 — 원격 관리는 설정·참조를 만지는 **로컬 쓰기**다).
  `LocalGitEngine.list_remotes_with_urls() / add_remote / remove_remote /
  set_remote_url`, 전부 WriteQueue 경유(조회 제외).
- UI: 저장소 메뉴 "원격 관리..." 다이얼로그 — 목록 + 추가/주소 변경/삭제.
  변경 후 refs·그래프 재로딩(원격 추적 참조가 변했다).
- 검증: 이름 중복·빈 URL은 엔진이 조치를 실은 오류로 거부.

## F2 — 파일시스템 감시 (backlog §2.3)

### 요구사항

- FR-03 앱 밖(CLI)에서 만든 커밋·브랜치 전환·fetch가 F5 없이 화면에
  반영된다.
- FR-04 앱 자신의 쓰기가 유발한 이벤트로 이중 재로딩하지 않는다.
- AC-02 외부 `git commit` 후 수 초 안에 그래프에 새 커밋이 나타난다.
  앱 내부 커밋은 재로딩이 **한 번**만 일어난다.

### 설계 (ADR-85)

- **watchdog을 들이지 않는다** — 결정 사다리 4단: Qt 내장
  `QFileSystemWatcher`로 충분하다. 감시 대상은 워킹 트리 전체가 아니라
  **`.git`의 핵심 신호**다: gitdir 자체(디렉터리 — HEAD·MERGE_HEAD 등
  원자적 rename이 directoryChanged로 잡힌다), `packed-refs`,
  `refs/heads`. 워킹 트리 수만 파일을 감시하는 것은 fd 낭비이고, 워킹
  트리 편집의 반영은 **창 활성화 시 상태 재로딩**이 담당한다(편집기에서
  돌아오는 순간이 사용자가 최신 상태를 기대하는 순간이다).
- **디바운스 800ms** — CLI 작업 하나가 이벤트 여러 개를 만든다.
- **자기 유발 억제**: 쓰기 큐·원격 워커·로딩 중이면 무시한다 — 그
  경로들은 끝나면 스스로 재로딩한다. 유휴 repack 중 이벤트도 같은
  가드에 걸린다.
- QFileSystemWatcher는 rename된 파일을 감시 목록에서 떨군다 —
  이벤트마다 경로를 다시 등록한다.

## F3 — 줄 단위로 골라 합치기 (backlog §2.2)

### 요구사항

- FR-05 마커가 있는 텍스트 충돌에서 충돌 구획마다 내 것/상대 것/양쪽을
  골라 합칠 수 있다 — 편집기 없이.
- FR-06 마커 없는 충돌(바이너리·삭제 계열)에는 이 경로를 내밀지 않는다
  (기존 한쪽 선택이 그쪽 담당이다).
- AC-03 구획 A는 내 것, 구획 B는 상대 것을 골라 적용하면 워킹 트리
  파일이 그 조합이 되고 스테이징되어 충돌이 풀린다. diff3 스타일
  (`|||||||` 구획)도 성립한다.

### 설계

- **워킹 트리의 마커 파일을 파싱한다** — git이 이미 3-way 병합을 끝내고
  공통 부분을 짜 놓았다. 인덱스 스테이지에서 다시 합치는 것은 그 일을
  중복하는 것이다. `domain/conflict_text.py`(순수 파이썬):
  `parse_conflicted(text) → 구획 목록(공통/충돌{ours,theirs,base?})`,
  `compose(구획, 선택) → text`. diff3의 `|||||||`~`=======`는 base로
  읽고 버린다. 마커가 중첩·불완전하면 파싱 오류 — 조치를 실은 오류로
  거부한다(반쯤 합친 파일을 쓰지 않는다).
- 엔진 `resolve_conflict_lines(path, choices)`: 파싱→선택 검증(구획 수
  일치)→합성→워킹 트리에 쓰기→스테이징(기존 `resolve_conflict`의
  모드 보존 규칙(ADR-66) 재사용). WriteQueue 경유.
- UI: ConflictPanel에 "줄 단위로 고르기..." 버튼(텍스트+마커 충돌에서만
  활성). 다이얼로그: 구획마다 내 것/상대 것/양쪽 라디오 + 양쪽 내용
  미리보기, 적용 시 시그널로 MainWindow에 위임.
- 사용자가 워킹 파일을 이미 편집했다면(기존 `_working_copy_edited`)
  파싱 결과가 편집을 덮는다 — 같은 확인 절차를 거친다.
