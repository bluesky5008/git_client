# 요구사항 — backlog §4(목적 함수 최적화) + §5(UI 미구현)

> 기준선: v1 (2026-07-31 승인 — 구현 범위: P1·P2·U1·U2 이번 회차, P3·U3~U5 설계만)
> 작업-ID: 20260731-backlog-opt-ui
> 상위 문서: design.md v2.6, performance.md §9, backlog §4·§5

## 문제와 목적

backlog §4의 최적화 6건과 §5의 UI 5건이 미구현으로 남아 있다. 목적 함수
(사용자가 네트워크를 기다리는 시간, ADR-56)에 직접 닿는 것부터 순서대로
해소한다. 전부 한 번에가 아니라 **증분으로 나눠 각 증분이 독립적으로
완결·검증되도록** 한다.

## 기능 요구사항

### 증분 P1 — 설정형 최적화와 판정 (backlog §4)

- FR-01 fetch 계열 명령이 `fetch.negotiationAlgorithm=skipping`을 쓴다 —
  단, **협상 왕복 감소가 실측으로 확인되는 경우에만 채택**한다
  (계측: `negotiation_rounds`, 이번에 복구됨).
- FR-02 POSIX에서 ssh 원격에 연결 멀티플렉싱(ControlMaster)을 적용한다.
  Windows OpenSSH는 미지원이므로 제외한다. 실측 불가 환경(로컬에 ssh
  원격 없음)이므로 🔶 잠정으로 채택하고 근거를 기록한다.
- FR-03 `core.fsmonitor`/`untrackedCache`는 **판정**한다: 앱의 status가
  pygit2 경로라면 소비자가 없다 — 채택이 아니라 §7(다시 논의하지 않음)로
  옮기고 재평가 조건(파일시스템 감시 도입 시)을 남긴다.
- FR-04 commit-graph `--changed-paths`는 ADR-14대로 소비 기능 등장 시까지
  보류를 유지한다 (문서 확인만).

### 증분 P2 — 중복 fetch 억제 (backlog §4)

- FR-05 사용자가 fetch/pull을 시작할 때 같은 원격의 prefetch가 진행
  중이면 **취소하지 않고 승격**한다: prefetch의 완료를 기다려(진행률을
  화면에 연결) 끝난 뒤 실제 fetch를 이어 돌린다. 이미 회선에 실린
  바이트를 버리지 않는다 (ADR-49와 같은 철학).
- FR-06 다른 원격을 향한 prefetch는 기존대로 즉시 양보(취소)한다.
- FR-07 승격된 prefetch도 취소 버튼으로 즉시 중단할 수 있다.

### 증분 P3 — 유휴 repack (backlog §4)

- FR-08 앱이 유휴(원격 작업·쓰기 큐·진행 중 연산 없음)일 때 저장소를
  `git repack`으로 정돈하고, 이때만 델타 설정(`pack.window`/`pack.depth`,
  ADR-35)을 쓴다. 사용자 작업이 시작되면 즉시 양보한다.

### 증분 U1 — reflog 탐색 (backlog §5, Phase 4 잔여)

- FR-09 HEAD reflog를 앱 안에서 볼 수 있다 (시각, 메시지, sha).
- FR-10 reflog 항목에서 "이 커밋에서 브랜치 만들기"로 잃은 커밋을
  복구할 수 있다 — reset·건너뛰기가 만든 손실의 복구 짝 (ADR-76의 안내
  문구가 가리키는 곳).

### 증분 U2 — 실행된 git 명령 로그 패널 (backlog §5)

- FR-11 앱이 실행한 git CLI 명령(원격·시퀀서)을 시각·소요·종료 코드와
  함께 패널에서 볼 수 있다 (§5.2 원칙 3 — 투명성).
- FR-12 명령 표시에서 원격 URL의 userinfo(토큰 등)는 가린다.

### 증분 U3~U5 — 이후 회차 (설계만 이번에)

- FR-13 커밋 검색(메시지·sha·작성자) 및 최근 저장소 전환 드롭다운 (U3)
- FR-14 설정 화면 + 라이트/다크 테마 (U4)
- FR-15 단축키 설정·다국어·브랜치 드래그 앤 드롭 (U5)

## 비기능 요구사항

- NFR-01 모든 증분은 G4(UI 단일 블로킹 ≤ 50ms)를 지킨다 — reflog·로그
  패널의 데이터 적재는 워커 또는 상한이 있는 호출만.
- NFR-02 최적화 채택은 `절약한 전송 시간 > 추가 CPU 시간` 판정을 따르고
  (§1.4 원칙 1), 실측 불가 항목은 🔶로 남긴다.
- NFR-03 배경 작업(P2 승격 제외, P3)은 사용자 작업에 즉시 양보한다.

## 범위 밖

## 인수 조건

- AC-01 (P1) 협상 실측에서 skipping의 라운드 수 ≤ 기본값. 감소가 없으면
  채택하지 않고 결과를 기록한다.
- AC-02 (P1) POSIX에서 원격 명령의 GIT_SSH_COMMAND에 멀티플렉싱 옵션이
  포함되고, Windows(os.name=="nt")에서는 포함되지 않는다.
- AC-03 (P2) 같은 원격의 prefetch 진행 중 fetch를 시작하면 prefetch가
  취소되지 않고, 완료 후 fetch가 이어지며, 두 전송의 합계가 계측에
  남는다. 취소 버튼은 승격된 작업도 멈춘다.
- AC-04 (P3) 유휴 repack 후 팩 파일 수가 줄고, 진행 중 사용자 fetch를
  시작하면 repack이 양보한다.
- AC-05 (U1) reset --hard로 잃은 커밋을 reflog 화면에서 찾아 브랜치로
  복구할 수 있다 (통합 테스트).
- AC-06 (U2) fetch 한 번 뒤 로그 패널에 해당 명령·종료 코드가 보이고,
  자격증명·토큰이 표시되지 않는다.
